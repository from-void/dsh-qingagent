# 设计决策记录

## P61：待审回合的用户可见收尾

待审提交继续调用 `exec.concludeTurn()`，不改变回合终结语义。用户可见的当前状态和下一步由工具卡完成态的第二行承载；叙述只说明已经发生的事和用户现在可做的操作，不承诺后续模型行为。面板结算侧文案留待 P59 的回合边界叙事统一设计。

### 工具卡的事件快照语义

工具卡语义 = 提交时刻的事件快照。卡片文案只允许引用两类数据：冻结在 meta 里的事实，和通过批次级身份（`patchIds`）与实时状态精确对表的结果；禁止用“文稿/会话的当前状态”推断“这张卡那一批”的结局，对不上批次时一律按“已过去”处理（无指路语）。这条约定来自 B3、P61-b、P61-c 三次同根事故。

不使用 `deferContext` 注入 `UserMessage` 伪造收尾语，理由如下：

1. `UserMessage` 的语义是“用户说了一句话”。模型会回应一个并不存在的用户输入，并把这段伪造交互写进对话历史，污染后续上下文。
2. 注入消息会额外触发一次模型步进，产生无必要的调用成本，同时重新打开 P45 已收紧的文本层攻击面。
3. `deferContext` 解决的是“下轮输入”，而本需求要补的是“本轮输出”；两者所处的回合边界不同，用途与需求错位。
